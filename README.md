# WISM (Web Interactive Storytelling Model) 🚀

  Интеллектуальная веб-платформа для сквозной генерации и интерактивного редактирования нелинейного мультимедийного контента на основе технологий генеративного ИИ.

Проект представляет собой практическую реализацию выпускной квалификационной работы бакалавра (МАИ, 2026 г.). Платформа позволяет авторам, геймдизайнерам и сценаристам проектировать сложные разветвленные сюжеты, автоматически генерировать текстовое наполнение с удержанием лора произведения и создавать визуальные раскадровки (сториборды) с гарантированным сохранением идентичности персонажей.

## Ключевые особенности и инновации

1. Поливариантный нарративный граф (Neo4j): в отличие от линейных текстовых редакторов, структура истории представлена в виде направленного графа. Специализированный мета-узел BranchSet изолирует логику сюжетных развилок, оптимизируя алгоритмы обхода графа.

2. Семантическая память и RAG (ChromaDB): двухэтапный конвейер контекстного обогащения. Перед отправкой запроса к LLM система автоматически собирает структурный контекст из графа и извлекает факты о лоре вселенной с помощью векторного поиска.

3. Визуальная консистентность персонажей (IP-Adapter): интеграция адаптеров изображений-промптов позволяет фиксировать биометрические параметры героев по единственному референсу «на лету» без вычислительно затратного дообучения нейросетевых весов (LoRA).

4. Бесконфликтная совместная работа (CRDT + Action Queue): синхронизация текстового и структурного наполнения в реальном времени на основе математических моделей CRDT по протоколу WebSockets. Очередь действий на клиенте предотвращает состояние гонки при тяжелых асинхронных генерациях.

5. Отказоустойчивая микросервисная оркестрация (Apache Kafka + Celery): распределенная шина данных на базе Kafka изолирует тяжелые фоновые процессы инференса нейросетей от синхронного API-потока.

## Технологический стек

### Frontend

- Фреймворк: Vue 3 (Composition API, Vite)

- Управление состоянием: Pinia (нормализованный кэш состояний)

- Синхронизация: ywebsocket (CRDT-библиотека Yjs)

- Стилизация: Tailwind CSS

### Backend & Orchestration

- Спецификация API: FastAPI (Python 3.11+, асинхронный стек)

- Шина сообщений: Apache Kafka (Event-Driven координация)

- Асинхронные задачи: Celery + Redis

- Объектное хранилище: MinIO (S3-совместимое хранение медиафайлов)

### Базы данных (Polyglot Persistence)

- Neo4j: Хранение топологии нелинейного сценария и связей сущностей.

- ChromaDB: Векторное хранилище эмбеддингов для RAG.

- PostgreSQL: Реляционная СУБД для системных метаданных и профилей пользователей.

### Назначение сервисов и хранилищ данных:

- Orchestrator (FastAPI): Единая точка входа API. Поддерживает дуплексные WebSocket-соединения с клиентами, проверяет авторизацию и транслирует высокоуровневые команды в разделы Kafka.

- Content Service (FastAPI + Celery): Обрабатывает логику структуры сценария. Пишет топологию в Neo4j, используя оптимизированные Cypher-скрипты, и фиксирует метаданные в PostgreSQL.

- Knowledge Service (FastAPI): Отвечает за индексацию лора, извлечение сущностей и семантический поиск эмбеддингов в ChromaDB.

- Media Service (FastAPI + Celery): Инкапсулирует тяжелый графический инференс (Stable Diffusion XL + IP-Adapter), сохраняет метаданные генерации в PostgreSQL и загружает бинарные объекты в MinIO S3 по S3 API.

## Быстрый запуск (Локальное развертывание)

Для локального запуска всей инфраструктуры (включая базы данных, брокеры сообщений и воркеры) в изолированных контейнерах подготовлен конфигурационный файл Docker Compose.

Требования

- Docker (v20.10+)

- Docker Compose (v2.20+)

- Зарегистрированные API-ключи для генеративных моделей (например, Google AI API / OpenAI)

## Инструкция по запуску

1. Клонируйте репозиторий:

```git
git clone https://github.com/Krolicc/WISM.git
cd WISM
```

2. Настройте переменные окружения: создайте файлы .env во вложенных директориях сервисов (по шаблону .env.example) и укажите ваши ключи доступа к API генеративных моделей и конфигурации баз данных.

3. Запустите контейнеры:
```git
docker-compose up --build -d
```

4. Проверьте статус сервисов:
```git
docker-compose ps
```
