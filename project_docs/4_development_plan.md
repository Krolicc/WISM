## План разработки

Этот раздел содержит дорожную карту развития проекта на ближайшие недели.

### Неделя 1: Полноценная интеграция Frontend-Backend и базовый CRUD

**Цель:** Полностью отказаться от `mock-api.ts` и перевести фронтенд на взаимодействие с реальным бэкендом, обеспечив персистентность всех данных.

*   **[Бэкенд]** Реализовать полный набор CRUD (Create, Read, Update, Delete) эндпоинтов для всех ключевых моделей: `Story`, `Chapter`, `Scene`, `Frame`.
*   **[Бэкенд]** Доработать эндпоинты для корректной обработки вложенных запросов (например, получение всех глав для истории, всех сцен для главы).
*   **[Фронтенд]** Создать централизованный сервис `api.ts` для отправки `fetch` запросов на бэкенд.
*   **[Фронтенд]** Переписать методы в хранилище `content.ts`, заменив вызовы `mock-api` на вызовы нового сервиса `api.ts`.
*   **[Интеграция]** Полностью удалить `mock-api.ts` после успешного перехода.
*   **[Интеграция]** Настроить и отладить обработку реальных состояний загрузки (`isLoading`) и ошибок (`error`) на стороне фронтенда.

### Недели 2-3: Реализация генерации изображений и основной бизнес-логики

**Цель:** Реализовать ключевую функцию продукта — генерацию изображений для кадров, и оживить логику регенерации контента.

*   **[Бэкенд]** Реализовать логику, обрабатывающую массив `regenerate_items` с флагами, для регенерации текстового контента сцен.
*   **[Бэкенд]** Реализовать эндпоинт, обрабатывающий вставку новых сцен/кадров в указанные пользователем места.
*   **[Бэкенд]** Исследовать и интегрировать сервис для генерации изображений (например, Stability AI, DALL-E 3, Midjourney API).
*   **[Бэкенд]** Создать эндпоинт, который принимает `detailed_prompt` кадра, генерирует по нему изображение и сохраняет URL в модели `Frame`.
*   **[Фронтенд]** В `FrameEditor.vue` добавить UI для запуска генерации изображения (например, кнопка на заглушке кадра).
*   **[Фронтенд]** Реализовать отображение сгенерированного изображения в `FrameEditor`, а также индикацию процесса генерации (спиннер).

### Идеи для дальнейшего роста (High-Impact Features)

*   **[UX/UI] Продвинутый редактор промптов**: Заменить `<textarea>` для `detailed_prompt` на структурированный UI-конструктор. Вместо редактирования "сырого" JSON, пользователь сможет заполнять отдельные поля: "Персонажи", "Окружение", "Действие", "Композиция кадра". Это кардинально улучшит UX.
*   **[Архитектура] Интерактивные статусы через Websockets**: Для длительных операций (генерация сюжета, генерация изображений) внедрить Websockets. Это позволит бэкенду отправлять на фронтенд обновления статуса в реальном времени (`Генерация... 35%`), что значительно улучшит пользовательский опыт.
*   **[Бэкенд] Система пользователей и аутентификация**: Внедрить систему пользователей (например, с помощью FastAPI-Users и JWT), чтобы каждый автор мог работать со своими историями, обеспечивая приватность и безопасность данных.
*   **[Качество] Внедрение тестирования**: Начать покрытие критической бизнес-логики на бэкенде юнит-тестами (`pytest`) и ключевых пользовательских сценариев на фронтенде E2E-тестами (`Cypress` или `Playwright`) для повышения стабильности проекта.

### Долгосрочное видение и креативные идеи
#### Интеллектуальная генерация 2.0
1.  **[AI] Консистентность персонажей (Character Lock)**: Разработка механизма (например, на основе LoRA или векторов встраивания), который "запоминает" внешность созданного персонажа и гарантирует его узнаваемость во всех последующих кадрах, даже в разных позах и с разными эмоциями.
2.  **[AI] Консистентность стиля (Style Lock)**: Возможность загрузить 3-5 изображений в определенном стиле, на основе которых AI создает "модель стиля" для всей истории. Это позволит генерировать комиксы в уникальной, авторской стилистике.
3.  **[AI] Динамический анализатор ритма (Pacing Advisor)**: AI, который анализирует сценарий и предлагает, где можно добавить "тихие" кадры для нагнетания атмосферы, а где, наоборот, ускорить повествование, объединив несколько действий в одном динамичном кадре.
4.  **[AI] Генератор компоновки панелей (Dynamic Layouts)**: Вместо статичных сеток, AI анализирует действие в сцене и предлагает несколько вариантов расположения и формы панелей на странице, чтобы наилучшим образом передать динамику (например, острые, диагональные панели для экшена).
5.  **[AI] "Оживление" кадра (Living Frames)**: Генерация не только статичных изображений, но и мелких анимированных элементов: дым, дождь, пар, а также автоматическое добавление текстовых звуковых эффектов ("BOOM!", "CRASH!") в соответствующем стиле.
6.  **[AI] Сценарный доктор (Story Doctor)**: Продвинутый AI-ассистент, способный проанализировать всю историю целиком на предмет сюжетных дыр, несостыковок в мотивации персонажей и проблем с темпом повествования, предлагая конкретные улучшения.
#### Экосистема и Сообщество
7.  **[Community] Торговая площадка (WISM Marketplace)**: Создание хаба, где пользователи могут делиться, покупать и продавать свои ассеты: обученные модели персонажей и стилей, сложные шаблоны промптов, готовые паки локаций.
8.  **[Community] Режим соавторства (Co-writing Mode)**: Реализация функционала совместной работы над одной историей в реальном времени, как в Google Docs, где один автор может писать сценарий, а другой — генерировать и редактировать кадры.
9.  **[Community] Публичный хаб историй (WISM Showcase)**: Создание общедоступной витрины, куда авторы могут публиковать свои законченные комиксы. С системой лайков, комментариев, подписок на авторов и возможностью для читателей поддерживать создателей материально (донаты).
10. **[UX] "Git для историй"**: Внедрение системы контроля версий для повествования. Авторы смогут создавать "ветки" сюжета, чтобы безопасно экспериментировать с альтернативными ходами ("Что, если бы герой проиграл эту битву?"), а затем сливать удачные изменения в основную историю.
11. **[Community] Еженедельные вызовы (Creative Prompts)**: Запуск еженедельных или ежемесячных конкурсов с заданными темами ("Создай 3-панельный хоррор", "Комикс в стиле нуар без диалогов"), чтобы стимулировать креативность сообщества и вовлекать пользователей.
#### Новые форматы и Продукты
12. **[Product] Генератор анимированных сторибордов (Animatic Exporter)**: Функция экспорта проекта не просто в виде картинок, а как видеофайл-аниматик, где кадры сменяют друг друга с базовыми переходами, а сгенерированные диалоги могут быть озвучены синтезированным голосом.
13. **[Product] Режим "Интерактивный комикс"**: Добавление функционала для создания ветвящихся нарративов в духе "выбери свое приключение". Читатель сможет делать выбор в ключевых точках, который будет вести его по разным сюжетным путям.
14. **[Product] Подготовка к печати (Print-Ready Export)**: Расширенный экспорт, который позволяет выгружать комикс в высоком разрешении с поддержкой цветового профиля CMYK, с настраиваемыми полями и метками для профессиональной типографской печати.
15. **[Product] API для разработчиков**: Предоставление публичного API, который позволит сторонним разработчикам использовать движок WISM для генерации нарративного контента в своих приложениях, играх или на сайтах.
16. **[Product] Режим "Вебтун/Манга"**: Специализированный режим редактора, адаптированный под форматы вертикальных вебтунов (бесконечный скролл) и классической манги (чтение справа налево, специфические стили и скринтоны).
17. **[AI/UX] Конструктор персонажей**: Вместо описания персонажа текстом — визуальный редактор, где пользователь "собирает" персонажа как в видеоигре (выбирает прическу, черты лица, одежду), а система сама генерирует соответствующий текстовый промпт и визуальный эмбеддинг.
18. **[Product] Образовательная платформа**: Создание отдельной версии платформы для учебных заведений, сфокусированной на обучении сторителлингу. С методическими материалами для учителей и упрощенным интерфейсом для учеников.
