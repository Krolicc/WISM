## 3. Деплой и настройка backend

**Дата:** ~ 18.02.2026 - 18.02.2026

После завершения рефакторинга следующей критической задачей стало развертывание бэкенд-приложения в облаке для интеграции с уже развернутым фронтендом. В качестве хостинг-платформы был выбран Render.

### 3.1. Настройка Docker для продакшена

Для развертывания на Render был выбран подход с использованием Docker, что обеспечивает консистентность окружения.

*   **Создание `Dockerfile`**: Был создан и итеративно улучшен `Dockerfile` для сборки и запуска приложения.
*   **Оптимизация установки зависимостей**: Решена ключевая проблема с `Poetry` внутри Docker. Команда `poetry config virtualenvs.create false` была добавлена, чтобы зависимости устанавливались напрямую в системный Python контейнера, что является стандартной практикой и повышает надежность.
*   **Корректировка команды запуска**: Команда запуска сервера прошла несколько итераций. Был убран флаг `--reload`, предназначенный только для разработки. Финальная команда в `ENTRYPOINT` была сформирована для соответствия требованиям Render:
    *   `poetry run alembic upgrade head`: Автоматическое применение миграций базы данных при старте контейнера.
    *   `poetry run uvicorn main:app --host 0.0.0.0 --port $PORT`: Запуск `uvicorn` на хосте `0.0.0.0` (чтобы принимать внешние подключения) и на порту, который динамически выдается платформой Render через переменную окружения `$PORT`.
*   **Выбор веб-сервера**: Изначально рассматривался `gunicorn` как более продакшен-ориентированный сервер, но после проверки зависимостей выяснилось, что он не установлен. Было принято верное решение вернуться к `uvicorn`, который уже присутствовал в проекте.

### 3.2. Развертывание на Render и отладка

*   **Первоначальная сборка**: После отправки `Dockerfile` на GitHub первая сборка на Render завершилась неудачно.
*   **Диагностика ошибки `ValidationError`**: После успешной сборки Docker-образа приложение не смогло запуститься, выдав ошибку `pydantic_core._pydentic_core.ValidationError: 1 validation error for Settings`. Это указало на проблему не в сборке, а в конфигурации приложения при запуске.
*   **Решение проблемы с переменными окружения**: Анализ файла `backend/app/core/config.py` показал, что приложение ожидает переменную окружения `google_api_key`. Ошибка возникала из-за того, что эта переменная не была установлена в настройках сервиса на Render. Было дано указание добавить ее через панель управления Render, с акцентом на важность **точности и регистрозависимости** имени переменной.

### 3.3. Настройка для локальной разработки и тестирования

Для обеспечения возможности тестирования публичного фронтенда с локально запущенным бэкендом были предприняты следующие шаги:

*   **Настройка CORS**: В `backend/main.py` в список разрешенных источников (CORS `origins`) был добавлен URL развернутого фронтенда (`https://wism-57279506-b6cba.web.app`). Это необходимо, чтобы браузер не блокировал запросы от фронтенда к API.
*   **Рекомендации по "туннелированию"**: Было объяснено, что для того, чтобы публичный сайт мог "видеть" локальный сервер, необходимо использовать сервисы-туннели, такие как `ngrok`, которые создают безопасный публичный URL для локального порта.
