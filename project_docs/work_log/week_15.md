# Неделя 15: Проектирование Долговременной Памяти и Контекста для ИИ

**Дата:** 05.03.2026 - ...

## Ключевая Проблема: Наивная Реализация Контекста

В ходе рефакторинга `BaseOrchestrationService` мы столкнулись с фундаментальной архитектурной проблемой. Наш план по рекурсивному сбору контекста путем постоянных запросов к реляционной базе данных (PostgreSQL) для получения описаний всех родительских элементов является:

1.  **Неэффективным:** Приводит к множеству последовательных SQL-запросов на каждом шаге генерации.
2.  **Немасштабируемым:** С ростом глубины и объема истории размер передаваемого в LLM контекста будет стремительно расти, что приведет к увеличению стоимости, задержек и риску превышения лимита токенов.
3.  **Контекстуально Ограниченным:** Такой подход предоставляет только "вертикальный" срез контекста (от истории к сцене), но упускает важный "горизонтальный" контекст (например, события из параллельной главы или описания ключевых персонажей).

## Исследование и Выбор Архитектуры Памяти

Мы провели исследование современных подходов к реализации долговременной памяти для LLM-систем, чтобы найти профессиональное и масштабируемое решение.

### Рассмотренные Варианты:

1.  **Векторные Базы Данных (Vector DB):** Стандарт индустрии для семантического поиска. Позволяют находить информацию не по ключевым словам, а по смысловой близости. Идеально для поиска релевантных "воспоминаний" или тематически похожих частей истории. (Примеры: ChromaDB, Pinecone, Weaviate).
2.  **Графы Знаний (Knowledge Graphs):** Хранение данных в виде узлов (сущностей) и ребер (отношений). Идеально для хранения и извлечения структурированных фактов и взаимосвязей (кто есть кто, где что находится, кому что принадлежит).
3.  **Гибридный Подход (Векторы + Графы):** Объединение двух вышеуказанных подходов для получения как тематического, так и фактического контекста.

### Принятое Решение:

Мы приняли решение двигаться в сторону **гибридной архитектуры памяти**, объединяющей Векторные Базы Данных и Графы Знаний. Это не только решает нашу текущую проблему, но и закладывает фундамент для будущих мощных функций, таких как управление персонажами и построение мира (world-building).

*   **Векторная База** будет отвечать за **связность повествования**.
*   **Граф Знаний** будет отвечать за **фактическую целостность мира**.

## План Поэтапной Реализации

Мы будем внедрять новую архитектуру в три фазы, чтобы обеспечить плавный переход и быструю доставку ценности.

### Фаза 1: Внедрение Векторной Базы (Ближайшая Цель)

**Задача:** Решить насущную проблему с эффективной и релевантной передачей контекста.

1.  **Интеграция:**
    *   Добавить в `docker-compose.yml` сервис для векторной базы данных. Наш выбор — **ChromaDB**, так как он прост в настройке и может работать локально без дополнительных зависимостей.
2.  **Индексация Контента:**
    *   Модифицировать `BaseOrchestrationService`. После успешного создания любого объекта в основной БД (Story, Chapter, Scene), мы будем создавать для его текстового описания векторное представление (embedding) и сохранять его в ChromaDB вместе с ID объекта.
3.  **Рефакторинг Сбора Контекста:**
    *   Полностью переписать метод `_get_full_context_prompt`. Вместо рекурсивных SQL-запросов он теперь будет:
        a.  Брать "идею" для нового контента.
        b.  Превращать ее в вектор.
        c.  Выполнять семантический поиск по ChromaDB для нахождения `k` наиболее релевантных фрагментов из уже существующей истории.
        d.  Формировать из найденных фрагментов финальный промпт для LLM.

### Фаза 2: Создание Базы Знаний (Среднесрочная Цель)

**Задача:** Начать структурировать информацию о мире комикса.

1.  **Реализация Графа Знаний:**
    *   Начать проектирование и реализацию простого графа знаний.
    *   Интегрировать его с функционалом **управления персонажами** и локациями. При создании или редактировании сущности, ее атрибуты и связи будут заноситься в граф.

### Фаза 3: Гибридный Поиск (Долгосрочная Цель)

**Задача:** Достичь максимального качества и осмысленности генерируемого контента.

1.  **Объединение Поисков:**
    *   Модифицировать систему сбора контекста для выполнения двойного запроса:
        1.  Семантический поиск по **Векторной Базе** для получения тематического контекста.
        2.  Фактический поиск по **Графу Знаний** для извлечения конкретных данных о задействованных в сцене сущностях.
    *   Объединять оба результата в один исчерпывающий промпт для LLM.

Этот план позволит нам построить передовую, умную и масштабируемую систему генерации контента.
