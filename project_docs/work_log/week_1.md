## 1. Проделанная работа: Интеграция генеративного AI для создания сюжетов

**Дата:** ~ 02.02.2026 - 02.02.2026

На этом начальном этапе мы заложили основу для генерации сюжетов с помощью искусственного интеллекта. Основная цель заключалась в том, чтобы создать гибкую и расширяемую архитектуру на бэкенде, которая могла бы легко адаптироваться к различным моделям и провайдерам AI.

### 1.1. Настройка окружения и зависимостей

*   **Настроен `Poetry`**: Инициализирован проект `backend` с помощью Poetry для управления зависимостями.
*   **Установлены ключевые библиотеки**: В проект добавлены `fastapi` и `uvicorn` для создания веб-сервера.
*   **Решена проблема структуры проекта**: Имя проекта в `pyproject.toml` было синхронизировано с именем папки (`backend`), чтобы исправить ошибку установки `poetry install`.

### 1.2. Исследование и выбор архитектуры для AI

*   **Обсуждение альтернатив**: Мы проанализировали различные подходы к интеграции AI: прямое использование SDK (например, `openai`) против фреймворков-абстракций (`LangChain`).
*   **Выбор `LangChain`**: Для обеспечения гибкости и возможности легкой смены AI-моделей в будущем был выбран фреймворк `LangChain`. Это позволяет нам строить сложные цепочки вызовов (например, "сюжет -> раскадровка -> изображение") и не быть привязанными к одному провайдеру.
*   **Выбор AI-провайдера**: Вместо платного OpenAI был выбран сервис `Groq`, предоставляющий бесплатный и очень быстрый доступ к передовым open-source моделям (Llama 3). Это идеально подходит для прототипирования и разработки.

### 1.3. Реализация на бэкенде

*   **Настройка конфигурации**: Создан файл `backend/config.py` с использованием `pydantic-settings` для безопасной загрузки API-ключа (`GROQ_API_KEY`) из `.env` файла.
*   **Создан сервис-генератор**: Вся логика взаимодействия с AI вынесена в `backend/services/story_service.py`.
*   **Реализована цепочка `LangChain`**: В сервисе настроена цепочка, которая:
    1.  Принимает пользовательский промпт.
    2.  Формирует системное сообщение для AI, инструктируя его быть сценаристом комиксов и структурировать ответ в 3 акта.
    3.  Использует модель `llama3-8b-8192` через `ChatGroq`.
    4.  Возвращает сгенерированный сюжет в виде чистого текста.
*   **Обновлен API-эндпоинт**: Эндпоинт `POST /api/v1/generate-story` в `backend/api/story.py` теперь вызывает `story_service` для получения реального, сгенерированного сюжета, заменяя собой первоначальные mock-данные.
