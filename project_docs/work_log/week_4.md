## 4. Устранение критической ошибки асинхронности (MissingGreenlet)

**Дата:** 18.02.2026

После интеграции генерации контента и связи моделей данных (`Story` -> `Chapter` -> `Scene` -> `Frame`) возникла критическая ошибка `sqlalchemy.exc.MissingGreenlet: greenlet_spawn has not been called`. Эта проблема блокировала ключевую функциональность приложения.

### 4.1. Диагностика проблемы

*   **Симптомы**: Ошибка возникала в конечной точке API (`/generate_content`) после того, как сервис генерировал новые главы и сцены для истории. Сбой происходил в момент, когда FastAPI пытался сериализовать (преобразовать в JSON) обновленный объект `Story` для отправки клиенту.
*   **Первопричина**: Ошибка `MissingGreenlet` — это классическая проблема при работе с `asyncio` и SQLAlchemy. Она возникает, когда SQLAlchemy пытается выполнить "ленивую" (lazy) загрузку связанных данных из базы данных в асинхронном контексте, где это запрещено. В нашем случае, после создания новых глав и сцен, FastAPI пытался получить доступ к этим новым связанным объектам, которые не были предварительно загружены.

### 4.2. Анализ и поиск решения

*   **Неудачные попытки**: Первоначальные гипотезы были сосредоточены на поверхностных исправлениях.
    1.  Добавление `selectinload` только для первого уровня вложенности (`Story.chapters`). Это не решило проблему, так как не загружались более глубокие связи (`scenes` и `frames`).
    2.  Использование `db.refresh(story)`. Этот метод обновляет только поля самого объекта, но не перезагружает его отношения, поэтому "ленивая" загрузка все равно происходила.
*   **Определение корневой причины**: После нескольких итераций стало ясно, что для успешной сериализации сложного вложенного объекта (`Story` со всеми его потомками) необходимо загрузить *всю иерархию данных* одним "жадным" (eager) запросом. Любая пропущенная связь в цепочке `Story` -> `Chapters` -> `Scenes` -> `Frames` приводила к попытке "ленивой" загрузки и, как следствие, к ошибке.

### 4.3. Реализация каскадной "жадной" загрузки

*   **Основное исправление**: Ключевое решение было реализовано в CRUD-слое (`backend/app/crud/`).
*   **`crud_story.py`**: В методах `get` и `get_multi` была реализована *цепочка* вызовов `selectinload` для загрузки всей иерархии:
    ```python
    options(
        selectinload(Story.chapters)
        .selectinload(Chapter.scenes)
        .selectinload(Scene.frames),
        selectinload(Story.characters)
    )
    ```
*   **`crud_chapter.py`**: Аналогичное исправление было применено и здесь, чтобы обеспечить полную загрузку данных при запросе отдельных глав.
*   **Использование `.unique()`**: В запросы было добавлено `.unique()`, чтобы SQLAlchemy корректно обрабатывал дубликаты, возникающие из-за `JOIN`'ов при "жадной" загрузке, и правильно собирал объекты.

### 4.4. Итог

Благодаря внедрению каскадной "жадной" загрузки для всех связанных моделей, проблема `MissingGreenlet` была полностью устранена. Теперь API может безопасно и предсказуемо возвращать полные, глубоко вложенные структуры данных, что является критически важным для работы фронтенда. Этот этап работы значительно повысил стабильность и надежность бэкенда.
