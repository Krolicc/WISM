## 6. Устранение проблем с окружением и комплексный рефакторинг UI

**Дата:** 19.02.2026

Этот этап был посвящен решению критических проблем с рабочим окружением, которые блокировали запуск бэкенда, а также масштабному улучшению пользовательского интерфейса для повышения его целостности и удобства использования.

### 6.1. Диагностика и устранение ошибки запуска бэкенда

*   **Проблема**: Приложение FastAPI не запускалось из-за ошибки `ImportError: libstdc++.so.6: cannot open shared object file`, связанной с отсутствием необходимой системной библиотеки в окружении Nix. Эта ошибка возникала из-за зависимостей `greenlet` и `sqlalchemy`.
*   **Итеративный поиск решения**:
    1.  **Добавление `pkgs.gcc`**: Первоначальная попытка решить проблему путем добавления `pkgs.gcc` в `.idx/dev.nix` не увенчалась успехом.
    2.  **Очистка кэша Poetry**: Была выдвинута и проверена гипотеза о поврежденном кэше `poetry`, но его очистка также не дала результата.
    3.  **Использование `pkgs.stdenv`**: Для предоставления полного стандартного окружения сборки в `.idx/dev.nix` был добавлен `pkgs.stdenv`. Это также не решило проблему окончательно.
    4.  **Явное указание `LD_LIBRARY_PATH`**: Критическим исправлением стало явное указание пути к библиотекам C++ через переменную окружения `LD_LIBRARY_PATH` в файле `.idx/dev.nix`. Это гарантировало, что Python сможет найти необходимые `.so` файлы во время выполнения.
*   **Результат**: Бэкенд-приложение успешно запустилось, разблокировав дальнейшую разработку.

### 6.2. Настройка автоматического запуска приложения

*   **Проблема**: Ранее для запуска приложения требовалось вручную выполнять несколько команд в терминале (`cd backend`, `poetry run ...`), что было неудобно и вело к ошибкам.
*   **Решение**: В файл `.idx/dev.nix` была добавлена конфигурация **предварительного просмотра (preview)**.
*   **Результат**: Теперь сервер разработки запускается автоматически, одной командой, с правильными параметрами (`--host`, `--port`) и в нужном окружении. Это значительно упростило процесс разработки и тестирования.

### 6.3. Редизайн и унификация иконок (`ActionsBar.vue`)

*   **Проблема**: Иконки на основной панели действий (`ActionsBar`) были неконсистентными и не передавали четкой иерархии (История -> Глава -> Сцена -> Кадр).
*   **Разработка визуальной системы**:
    *   **История**: 📖 Открытая книга.
    *   **Глава**: 📄 Страница с загнутым углом.
    *   **Сцена**: 🎬 Кинохлопушка (выполнено несколько итераций для достижения наилучшего вида).
    *   **Кадр**: 🎞️ Фрагмент кинопленки.
*   **Результат**: Создана логичная и стилистически целостная система иконок, которая интуитивно понятна пользователю.

### 6.4. Комплексный рефакторинг редактора кадров (`FrameEditor.vue`)

*   **Проблема**: Редактор кадров имел ряд недостатков: неудобное представление в виде списка, отсутствие тематического оформления и неинтуитивные иконки.
*   **Проведенные улучшения**:
    1.  **Новые иконки переключения вида**: Созданы и внедрены новые SVG-иконки для переключения между горизонтальным (`filmstrip`) и вертикальным (`list`) видами.
    2.  **Исправлена верстка списка**: Для режима списка (`list-view`) была ограничена максимальная ширина (`max-width: 800px`) и он был отцентрирован. Это решило проблему, когда список некрасиво растягивался на всю ширину экрана.
    3.  **Создана стилистика кинопленки**: Для режима `filmstrip-view` с помощью CSS-градиентов был создан эффект перфорации по краям, имитирующий настоящую кинопленку, что значительно улучшило визуальное погружение.
*   **Результат**: `FrameEditor` был полностью преображен, став более функциональным, эстетически приятным и соответствующим общей тематике приложения.
