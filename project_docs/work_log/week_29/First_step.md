Ниже представлен технический план реализации Этапа 1, исходя из предоставленного документа:

План реализации Этапа 1: MVP (Динамические промпты)
1. Проектирование Базы Данных (Backend)
Поскольку мы готовимся к будущему, структура должна позволять легко добавлять веса IP-Adapter или ID персонажа позже.

Таблица Characters

Таблица Generations: История созданных картинок, включая использованные промпты и ситуации.

id	        UUID	Уникальный ключ.
user_id	    FK	    Кто заказал генерацию.
status	    Enum	pending, processing, completed, failed.

2. Разработка Конструктора Промптов (Logic Layer)
Это сердце первого этапа. Нужно создать сервис-сборщик, который превращает клики в UI в понятный для SD текст.

Шаблонизатор персонажа: Функция, которая берет атрибуты (напр. elf, blue eyes) и оборачивает их в качественные ключевые слова (напр. masterpiece, high quality, (blue eyes:1.2)).

Библиотека ситуаций: Словарь пресетов для бэкенда.

Выбор «в кафе» → добавляет sitting in a cafe, drinking coffee, detailed background.

Валидатор: Проверка на конфликтующие теги, чтобы минимизировать риск «каши» (когда куртка становится цветом глаз).

3. Интеграция с GPU-воркером (Image Generation API)
Выбор модели: Настройка инстанса с быстрой моделью (SDXL Lightning или SD Turbo) для генерации за 1-2 секунды.

API Pipeline: Простая отправка текстового промпта (Text-to-Image) без использования дополнительных слоев типа ControlNet.

Обработка результата: Получение изображения, сохранение в S3-хранилище и передача ссылки клиенту.

4. Обновление Backend под CRDT (Текущая задача)
Параллельно с логикой генерации, внедряем поддержку CRDT для синхронизации состояния персонажа.

Это позволит в будущем нескольким пользователям или устройствам редактировать параметры героя без конфликтов версий.

---

API Endpoint: Бэкенд получает запрос с frame_id.

DB Fetch: Достаем данные кадра, персонажа и локации.

Prompt Build: Создаем финальную строку (промпт).

Generation Entry: Создаем запись в Generations со статусом pending.

AI Request: Отправляем JSON-конфиг в ComfyUI.

Polling/Webhook: Ждем готовности картинки.

Storage: Сохраняем картинку локально или в MinIO.

Update: Обновляем запись в Generations (статус success + image_url).
